# Debug E2E Fixtures

## Context
Playwright uses the local dump plus `e2e/fixtures/migrations/` and helper seeds.
Many failures are not product regressions; they are stale selectors, stale flow
expectations, or fixture rows missing a relationship the app now requires.

## Steps
1. Run the smallest failing spec first: `npm run test:e2e -- e2e/tests/<file>.spec.ts`.
2. Check whether the app behavior is already covered by unit tests before changing product code.
3. Fix fixture data at the missing relationship, not by weakening UI assertions.
4. Keep helper seeds aligned with source constants instead of copying date/year strings.
5. Re-run the changed spec, then the full `npm run test:e2e`.

## Gotchas
- Student e2e seeds must use `CURRENT_ACADEMIC_YEAR`; hard-coded academic-year strings can make `/api/pm/students` return an empty roster.
- Holistic fixture selection needs one School with an active supported-Program Centre, Batch membership, current-year Grade enrollment, and at least three eligible Students in each configured Grade. Seed that prerequisite roster before calling the shared Holistic fixture helper when the local dump does not provide it.
- `resetDatabase()` applies DB Service Holistic migrations from a sibling `../db-service_holistic_mentorship` checkout. If it is missing, symlink it to `../db-service` for the run (`ln -s db-service db-service_holistic_mentorship` from the parent folder) and remove the symlink afterwards.
- That step shells out to `mix`. The asdf shim fails there: no version is pinned for `db-service`, and its per-version `MIX_HOME` has no Hex. Put the real binaries first: `PATH="$HOME/.asdf/installs/elixir/1.18.4-otp-27/bin:$HOME/.asdf/installs/erlang/27.0/bin:$PATH" MIX_HOME=$HOME/.mix npx playwright test`.
- `relation "lms_student_intervention_flags" does not exist` in the webServer log (surfacing as browser 500s in the Holistic responsive/health test) means the local `e2e/fixtures/db-dump.sql` predates that table; nothing in the e2e migrations creates it. Refresh the dump rather than loosening the health assertions. `column s.tshirt_size does not exist` (a Next.js runtime-error overlay on `/centre/<id>`, so the Teacher's "Holistic Mentorship" tab never renders) is the same stale-dump problem: the uniform-size `student` columns come from db-service `20260925130000_add_uniform_sizes_and_g10_school_to_student`, and `resetDatabase()` only applies db-service `*holistic*` migrations. Run e2e from a worktree by symlinking the gitignored `.env.test` and the dump from the main checkout (and remove the symlinks after).
- A batch `enrollment_record.group_id` holds `batch.id`, not the batch `group.id`; join `batch ON batch.id = enrollment_record.group_id` (as `permissions.ts` does). Batch *membership* (`group_user`) is the one that goes through `"group".child_id`.
- The `pmPage` fixture owns no Schools or Centres on `/dashboard` ("My Schools 0", empty card grids). Use `adminPage` for dashboard card → destination journeys.
- Centre-seated Teachers are confined off `/school/<code>` (Access Denied); open their Holistic workspace at `/centre/<id>`.
- `seedHolisticFixtures()` upserts the shared fixture actors' permissions, so do not call it a second time for another Program. The EMRS (Program 78) Admin journey uses the separate `LMS78` scope seeded by `seedHolisticE2eEmrsScope()` in `e2e/helpers/db.ts`.
- Challenge Categories (#457) need the `holistic_mentorship_post_session_note_challenges` table from db-service #806 and the privacy tombstone's `post_session_challenges_erased` column (migration `20261026101410`), so the sibling DB Service checkout must include both; `resetDatabase()` applies them through its `*holistic*` migration glob. Without the table every Notes write fails; without the column every privacy erasure does. Only "Synthetic Grade 12 Active" carries prod-wording Questions (`seedHolisticE2eChallengeQuestions()`), so its groups sit above those Questions; every other Synthetic Phase shows the trailing "Challenge Categories" block. The seeded submitted Note on "Synthetic Grade 11 Completed" is the pre-release Note without Challenge Categories; specs that add Categories to it must delete its Category rows afterwards. The only fixture Note with Categories is the second Grade 12 Student's submitted Note on "Synthetic Grade 12 Skipped" (Phase 4): Exam/Test related issues + Time management & distractions. `holistic-challenge-categories.spec.ts` reads exact heatmap cells from it, so keep that Phase's other Notes without Challenge Categories. The fixture draft (second Grade 11 Student, "Synthetic Grade 11 Active") is submitted by `holistic-mentorship.spec.ts`, so a later spec that needs a draft must seed and delete its own.
- Holistic Student/Phase APIs return 422 without `program_id`; an access-denial assertion (404) must still send a valid Program.
- Centre-switcher journeys (#388) use `seedCentreSwitcherFixture()` / `removeCentreSwitcherFixture()` in `e2e/helpers/db.ts` (seed in `beforeAll`, remove in `afterAll` so other specs' Centre lists are unchanged) and `signInAs()` from `e2e/fixtures/auth.ts` for its synthetic seated and School-scoped users. Its "Switcher E2E …" Centres sit at Schools 19269/19006/19260, which no other fixture uses.
- The dashboard's default tab heading is "JNV NVS Schools"; "My Schools" is only the stat label.
- The Curriculum tab shows a Program selector only when the School has more than one Program from active physical Centres; single-Centre fixture Schools (e.g. `LMS75EMPTY`) have none.
- `column ser.sessions_applied does not exist` ("Failed to load student exam records for the roster" in the browser console, failing the Holistic health checks) is the same stale-dump problem for PR #436's exam registrations. Refresh the dump; to verify before a refresh, an uncommitted `99999999999999_tmp_exam_record_sessions_applied.sql` with `ALTER TABLE student_exam_record ADD COLUMN IF NOT EXISTS sessions_applied integer[];` unblocks them (2026-10-26); delete it afterwards.
- Curriculum topics need `topic_curriculum` rows in the fixture migration, not just `chapter` and `topic` rows.
- `column s.tshirt_size does not exist` (42703 from `src/lib/school-students.ts` via `RosterPage`) means the local `e2e/fixtures/db-dump.sql` predates the db-service Student coaching fields; every School/Centre page spec (school, curriculum School tab, dashboard card journeys, centre switcher, performance, Student-interaction visits, Holistic responsive) then fails, about 33 tests on 2026-10-19. Refresh the dump; do not patch the specs. To verify locally before a refresh, an uncommitted throwaway migration (e.g. `99999999999999_tmp_student_columns.sql` adding `student.tshirt_size`, `track_pant_size`, `monthly_family_income` as `text`) unblocks those pages; delete it afterwards.
- Toggling an `lms_chapter_exam_configs` row out of syllabus in a spec must also set `prescribed_minutes = 0` (`lms_chapter_exam_configs_out_of_syllabus_minutes_check`); restore the original minutes in a `finally` so later specs keep the fixture syllabus (see `e2e/tests/curriculum-plans.spec.ts`).
- Plan Assignment e2e (`curriculum-plans.spec.ts`, #423) seeds its own JNV Schools (900091–900093, regions `PLAN_E2E_NORTH`/`PLAN_E2E_SOUTH`) and "Plan Assign E2E …" Centres in a describe-level `beforeAll` and removes them in `afterAll`: Admin Curriculum Summary scope spans every JNV School, so leftover fixture Schools would add rows to other specs. Assignment rows are unique per Centre + Grade + academic year across all plans, so each test clears the fixture Centres' assignments in `beforeEach`. The Centre coverage block (#424) reuses the same fixture; Alpha also maps Grade 12 NEET so one Centre shows both Grades, and coverage rows are filtered by the "Plan Assign E2E " prefix because the dump's real JNV Centres are listed too.
- Curriculum Summary e2e (`curriculum-summary.spec.ts`, #426) relies on the SQL fixture `20261019130000_seed_curriculum_summary_fixture.sql`: "Summary E2E …" Centres at JNV Schools 900081–900086 (region `SUMMARY_E2E`; 900084 is `SUMMARY_E2E_OTHER` for scope), plans 900001–900004 and their completions. Its content is NEET-only on Grade 11 (plus a NEET config on Fixture Alpha Physics) and JEE Main Maths on Grade 12 so the teacher-logging and plan-authoring Chapter lists stay unchanged. Header numbers use a spec-seeded PM scoped to `SUMMARY_E2E`; the Admin pagination test counts every Grade 11 row in the e2e DB (13), so a spec that leaves extra Centres with Grade 11 Exam Tracks behind breaks it. The LMS fixture CoE/Nodal Centres map Grade 11 JEE Main + JEE Advanced and are Summary setup errors. Chapter tests overdue (#428) come from `20261019140000_seed_curriculum_summary_chapter_tests.sql`: batches 90009201–90009204 (`SUMB-…` codes) linked to Schools 900081–900083 via `school_batch`, CMS test / problem resources 90009001–90009013 with `resource_chapter` rows, a duplicate Bio Cells Chapter 90008107 (same code), sessions 90009101–90009113 (counted, scheduled, never-counting, multi-Centre and the three Chapter-mapping fallbacks) and a 5 Aug test date on Bio Animals in plan 900001. Adding a chapter-test session on those batches, or a test date on plan 900001, changes the hand-worked Tests overdue literals. The chapter timeline (#429) adds `20261019150000_seed_curriculum_timeline_fixture.sql`: two undated Grade 11 NEET Chapters (Bio Ecology 90008108, Chem Organic 90008109) that plan 900001 leaves undated, so the timeline literals (row order, Syllabus done 4/10) count them; a new in-syllabus Grade 11 JEE Main / NEET Chapter changes those literals. Timeline hours (#430) come from `20261019160000_seed_curriculum_timeline_hours_fixture.sql`: LMS Curriculum Logs 90008301–90008324 at SUMM81 / Program 2 / Grade 11 (Anand Shared) under JEE Main, NEET and one JEE Advanced (never counted), plus Bio Cells / Plants topics 900081031–900081041; a new log at that scope changes the hours, cancellation and doubt-solving literals. `20261019170000_seed_curriculum_summary_as_of_fixture.sql` (final checks) dates sessions 90009101–90009113's `inserted_at` to 1 Jun 2026 (a session counts for an as-of only once created or started, so fixture sessions inserted at `NOW()` would vanish from every past as-of) and adds sessions 90009114 (next academic year), 90009115 (created 18 Aug) and 90009116 (unified-majority test 90009007, problems 90009014–90009018), plus 21 Aug logs 90008331–90008333 under the duplicate Bio Cells row. New fixture sessions need an explicit past `inserted_at`. The 10h / 14h / 8h Primary Exam Track check seeds its own Grade 12 Schools 900088–900089 (region `SUMMARY_HOURS_E2E`), Centres 9000881/9000882/9000891 and Chapter 90008801 in a describe-level `beforeAll` and deletes them in `afterAll`, so Grade 12 Summary literals and the School Curriculum tab's Grade 12 subject default stay unchanged. The shared JEE Advanced + NEET class (Q20) comes from `20261019180000_seed_curriculum_summary_advanced_neet_fixture.sql`: School 900087 (`SUMM87`, region `SUMMARY_ADV_E2E`, outside the PM's scope), Centre 9000871 mapping Grade 12 JEE Advanced + NEET, a JEE Advanced-only Grade 12 Physics Chapter 90008701 (Optics, 2h; nothing new on JEE Main or NEET), Active plan 900005 (Optics + Fixture Biology) and Optics completions under both tracks. It is Grade 12 so the Admin's 13 Grade 11 rows don't move; its spec asserts under `q=SUMM87`, and the 10h / 14h / 8h check also expects 14h for it.
- `getByRole("alert")` also matches Next's route announcer, so it hits strict-mode violations; give inline error panels a `data-testid` and target that.
- Responsive visit lists can render hidden duplicate links; target visible links or rows.
- Program-admin `/visits` redirects to `/school-visit-summary`; go directly to visit detail when asserting read-only access.
- Blended Learning tables come from `e2e/fixtures/migrations/20261022130000_add_blended_learning_schema.sql` and the seed in `e2e/helpers/blended-learning-fixtures.ts` (run by `resetDatabase()` after `seedHolisticFixtures`, which creates the Mentor persona). Fixture dates are IST-day offsets from the seed's IST today, so a run that crosses IST midnight can shift by a day. If db-service changes those tables, re-diff with `patterns/mirror-db-service-schema-in-e2e.md`. The seed's Conversation and Attempt rows are append-only (the PR #804 trigger raises `23514` on UPDATE/DELETE), so insert them in final form; a done Action Item needs its completing Conversation inserted first. Photo rows have no S3 object: the Playwright web server presigns against a fake bucket and specs stub `amazonaws.com` with `page.route`.
- The test DB is reset once per run and Blended rows cannot be deleted, so a Blended spec that saves entries changes later specs' fixture facts (specs run alphabetically). Give a writing spec its own Mentor and Mentees, one set per viewport — as `BLENDED_MENTOR_C` / `LOGGING_MENTEES` do for `blended-learning-log-entry.spec.ts` (#445) and `ACTION_ITEM_MENTEES` do for `blended-learning-action-items.spec.ts` (#446) and `FLAG_MENTEES` for `blended-learning-mentor-flags.spec.ts` (#447) — and never assert on another spec's writable rows. Native `sr-only` radios make `locator.check()` time out ("label intercepts pointer events"); keep the radio visible, as `RadioPair` does. Tiptap toolbar buttons need `onMouseDown` `preventDefault`, otherwise keys typed right after a toolbar click are lost while `focus()` waits a frame.
- `blended-learning-manage.spec.ts` pushes Common Action Items only to Mentor D's `MANAGE_MENTEES`, never to "all" or a grade (that would add open items to every other spec's Mentees), and deletes the Resources it adds; previews for "all"/grade are read-only API calls. Its specs run serially (`describe.configure({ mode: "serial" })`), so one failure skips the rest.
- Visit action schemas should match the canonical validator shape; do not revive older legacy payload forms just to make an e2e pass.
